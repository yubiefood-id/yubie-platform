# Biteship onboarding + activation manual (operator-only)

Private operator checklist for ADR-014 shipping execution. Keep credentials,
exact addresses and customer data OUT of this repository and OUT of chat —
use the server secret store (/etc/yubie/production.env) and private operator
storage only.

## 0. Prerequisites (owner decisions, recorded once)

- [ ] Approved pickup origin: full address, postal code, contact name/phone,
      pickup hours, and (for instant couriers later) coordinates.
- [ ] Per-SKU logistics data: real weight (g) and dimensions (cm) per
      sellable SKU, packaging, storage class (`shelf_stable` only until
      transit handling for chilled/frozen is approved by food QA).
- [ ] Approved courier list (max 3 active on Starter) + insurance policy.
- [ ] Finance/PKP tax treatment record (default today: non-PKP, no tax line).

## 1. Biteship account (BLOCKED_EXTERNAL until done)

1. Register at biteship.com → subscribe **Starter** (verify current quotas
   in the dashboard: announced 100 shipments/month, 3 couriers, 2 origins —
   never assumed by code).
2. Create a **sandbox API key** (dashboard → Developers).
3. Configure the webhook: URL `https://api.yubiefood.com/v1/webhooks/biteship`,
   custom header `x-biteship-secret` (or change `BITESHIP_WEBHOOK_SECRET_HEADER`),
   secret value generated by your password manager.
4. Top up the wallet per Finance arrangement (bookings fail without balance).

## 2. Server configuration (per environment file)

~~~bash
SHIPPING_EXECUTION_MODE=disabled        # shadow -> sandbox -> pilot -> enabled
SHIPPING_PROVIDER=biteship
BITESHIP_ENV=sandbox                    # production only after activation
BITESHIP_API_KEY=<server secret only>
BITESHIP_API_BASE_URL=https://api.biteship.com
BITESHIP_WEBHOOK_SECRET=<server secret only>
BITESHIP_WEBHOOK_SECRET_HEADER=x-biteship-secret
SHIPPING_PILOT_MAX_BOOKINGS=5           # pilot mode only
SHIPPING_PILOT_BUDGET_IDR=500000        # pilot mode only
~~~

Startup fails closed on any typo or half-configuration (config package).

## 3. Data seeding (operator SQL via reviewed migration/ops channel)

- `shipping_origins`: one active row (is_active=true) with the approved
  origin; coordinates only when instant pickup is enabled.
- `sku_shipping_profiles`: one row per sellable SKU
  (YBF-250, YBF-1000, YBS-045, YBS-7X45, YBP-MINI-035, YBP-MAXI,
  YBP-MINI-5, YBM-* mie SKUs) — verify SKU codes against
  `packages/domain/src/product-discovery.ts` before inserting.
- Free-city coverage rows (`shipping_policy_approvals`) stay the authority
  for `free_promotional` cities; courier quotes only appear for uncovered
  destinations.

## 4. Mode ladder (each step has its own abort)

1. `disabled` — deploy baseline; webhooks/reconciliation only.
2. `shadow` — rate quotes visible in logs/metrics; NO bookings ever.
3. `sandbox` — real Biteship sandbox key: create test orders, simulate
   **one DELIVERED and one CANCELLED** in the dashboard (order detail →
   Simulate) and record both provider order ids as activation evidence.
4. Ask Biteship support (with the two order ids) to approve the
   **production API key**; switch `BITESHIP_ENV=production`.
5. `pilot` — bounded real bookings (`SHIPPING_PILOT_MAX_BOOKINGS`,
   `SHIPPING_PILOT_BUDGET_IDR`); watch one physical pickup end-to-end.
6. `enabled` — steady state after pilot review.

Rollback at any step: set `SHIPPING_EXECUTION_MODE=disabled` and recreate
the api+worker containers (bookings stop immediately; inbound webhooks and
reconciliation keep running). Code rollback is safe: schema 0027 is
additive-only.

## 5. Acceptance evidence to file (docs/shipping/EVIDENCE_LEDGER.md)

- Sandbox Delivered + Cancelled provider order ids.
- Pilot order id + waybill + webhook milestones (picked/delivered).
- Deploy receipts (SHA, digests, migration version) after each release.

## What staff does after activation (the whole point)

Paid order appears in admin → staff packs and marks `packed` → the system
books the courier pickup automatically → waybill appears in the order view
and on the customer's status page. Staff never opens JNE/GoSend/Lalamove
apps for normal dispatch.
